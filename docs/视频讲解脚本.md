**画面**：浏览器打开 `http://127.0.0.1:5173`，停在欢迎页。

**讲解词**：
> 这是我做的编程学习助手 CodeMentor。

## 三、阶段一：多模型接入与 Key 本地加密（4:30 – 7:00）

**画面**：先演示界面，再切代码。

**操作**：
1. 点左下角模型芯片 → 弹出设置。
2. 左侧列表指出六个供应商：DeepSeek、通义千问、OpenAI 兼容、Ollama 本地、自定义、内置演示。
3. 选中 DeepSeek，填一个假 Key，点「保存配置」，指出显示成 `sk-te****cdef`。
4. 点「测试连接」看到失败提示（假 Key 必然失败），说明错误提示是可读的。
5. 点「清除」，再切回内置演示模型。
6. 打开数据库看 `provider_configs` 表：`api_key_enc` 是密文。
7. 切代码：`app/api/routes/providers.py` → `app/core/security.py`。

**讲解词**：
> 阶段一要求多种云端和本地模型入口，还要能随时切换、Key 能存本地、即开即用。
> 这里六个供应商都是数据驱动的，加一家只需要在 registry 里加一条。切换就是更新 is_active 标记，只允许一个激活。
> Key 的处理是重点：前端只提交一次明文，后端用 Fernet 对称加密后存进 MySQL，加密密钥是本地文件 data/.fernet.key 里随机生成的。接口返回给前端的一律是掩码，数据库里看到的是密文。
> 为什么不是直接存明文？因为作业要求「保存到本地」不等于「明文裸奔」。重启服务时自动解密还原，所以是即开即用，同时不泄露。
> 另外一个细节：所有模型厂商的错误都会被翻译成人话，比如 401 会说「API Key 无效或已失效」，而不是抛一个 SDK 的原始异常。

**代码位置**：
- `backend/app/llm/registry.py`：供应商目录
- `backend/app/core/security.py`：`encrypt_secret` / `decrypt_secret` / `mask_secret`
- `backend/app/api/routes/providers.py`：保存、切换、测试
- `backend/app/llm/service.py`：`resolve_model`、`friendly_error`

## 五、核心：LangGraph 编排（9:30 – 13:00）★ 重点段落

**画面**：VS Code 打开 `backend/app/agent/graph.py`。

**操作**：
1. 先讲 `AgentState` 定义。
2. 逐个讲四个节点：`plan_node`、`act_node`、`tools_node`、`answer_node`。
3. 讲条件边 `route_after_act` 和 `tools → act` 的闭环。
4. 打开 `prompts.py` 讲三段式提示词。
5. 回到界面，重新问一个问题，让它慢一点，指着右侧「执行链路」说这就是图在跑。

**讲解词**：
> 这是整个项目的核心。作业要求「体现自主规划：模型先拆解任务，再逐步执行，而不是一次回答」，我用 LangGraph 的状态图来实现。
> 状态里存四样东西：计划、工具消息、迭代次数、最终答案。注意 tool_messages 用了 operator.add 作为 reducer，所以每个节点返回的是追加而不是覆盖。
> 第一个节点 plan：把问题、历史摘要、长期记忆、可用工具列表一起给规划模型，要求它只输出 JSON，包含 goal、steps、need_demo。解析失败有兜底计划，所以模型抽风也不会崩。
> 第二个节点 act：把工具绑定到模型上，让它决定要不要调用、调用哪个、参数是什么。如果返回了 tool_calls 就走 tools 节点，否则直接去 answer。
> 第三个节点 tools：逐个执行，把结果包装成 ToolMessage 塞回状态。这里是对异常的第一道防线，等下细说。
> 然后从 tools 回到 act，形成真实的多轮工具调用闭环，最多 6 轮，recursion_limit 兜底防死循环。
> 第四个节点 answer：把计划、工具证据、长期记忆、会话摘要全部塞进提示词，流式生成最终答案，每个 token 都通过 SSE 推给前端，所以用户看到的是打字机效果。
> 这样设计的好处是过程完全可观测：用户能看到 AI 先承诺了哪几步、哪一步真的调了工具、哪一步失败了。这在教学场景里很重要——学习者能学会「遇到问题该怎么拆」。

**代码位置**：
- `backend/app/agent/graph.py`：`build_graph`、`route_after_act`
- `backend/app/agent/prompts.py`：`PLANNER_PROMPT` / `ACTOR_PROMPT` / `ANSWER_PROMPT`
- `backend/app/agent/runtime.py`：运行时依赖打包

## 七、RAG 与 Qdrant（15:30 – 17:30）

**画面**：先演示「知识库」标签页，再切代码。

**操作**：
1. 展示统计：10 篇文档 / 17 个切片 / 17 个向量点，`Qdrant local` + `hash-ngram · 512 维`。
2. 在「检索测试」里输入 `装饰器 闭包`，展示命中的标题和分数。
3. 点「重建索引」。
4. 切代码：`rag/chunker.py`（代码块整体保留）、`rag/embeddings.py`（哈希向量）、`rag/store.py`（Qdrant 封装、混合检索）。

**讲解词**：
> RAG 这块分四步：切片、向量化、入库、检索。
> 切片有个坑我踩过：直接按空行切，会把代码块从中间切开。所以我的做法是先把代码围栏抽成占位符，切完再还原，并且长度按还原后的真实文本算，避免出现一大块超长切片。单元测试里专门有一条断言代码块完整性。
> 向量化默认用离线哈希向量：中文按一到两字滑窗、英文按标识符切词，用 blake2b 哈希到 512 维再做 L2 归一化。这么做是因为教学环境经常连不上 HuggingFace，下载不了 sentence-transformers；哈希向量零依赖、结果确定，对技术问答这种词面重合度高的场景够用。想要更强语义，把 EMBEDDING_PROVIDER 改成 api，就能切到千问的 text-embedding-v3。
> 检索用了混合策略：先用向量召回四倍的候选，再用「0.62 乘余弦相似度 + 0.38 乘关键词重合度」重排。纯向量对错误码、专有名词不敏感，加关键词重排明显更稳。你在检索测试里看到的分数就是这个混合分。
> 存储用 Qdrant，两个集合：知识库和长期记忆。点 ID 用 uuid5 从 doc_id 和切片序号推导，所以重复入库是覆盖而不是新增。默认用官方 embedded 模式落盘，改 QDRANT_MODE=remote 就能连服务端。

**代码位置**：`backend/app/rag/chunker.py`、`embeddings.py`、`store.py`、`seed.py`。

## 九、阶段五 + 六：屏幕演示（18:30 – 23:00）★ 第二个重点段落

**画面**：回到刚才那条带代码的回答。

**操作**：
1. 指着消息下方「可以启动屏幕演示」卡片，念出它可以演示的 3 个步骤。
2. 先举一个反例：问 `什么是闭包？`（纯理论），指出卡片显示「本轮不提供屏幕演示」。
3. 点「启动演示」→ 控制台弹窗 → 勾选「演练模式」→ 启动。
4. 展示：左侧实时画面刷新、右侧步骤时间线一条条增加、顶部步数进度。
5. 点「暂停」，指出提示「已在第 N 步暂停」。
6. 点「继续」，指出它是从暂停点继续，而不是从头开始。
7. 拖动「识别间隔」滑杆，说明可以调节识别频率。
8. 关闭演练模式，再真实跑一次（鼠标会真的动）。
9. 切代码：`demo.py`（判定逻辑）、`controller.py::_loop`（循环与暂停）、`actions.py`（动作执行）。

**讲解词**：
> 阶段五是屏幕控制，阶段六是把它接进智能体。作业对阶段六有两个硬约束，我都落在代码里了。
> 第一个约束：**必须等对话输出完毕，而且基于实际有效内容才能弹出启动选项**。你刚看到的反例很关键——问「什么是闭包」这种纯理论问题，是不会弹按钮的，只会显示「本轮不提供屏幕演示」。
> 判断逻辑在 demo.py：有代码块加 3 分，有两个以上编号步骤加 2 分，出现「打开、新建、粘贴、运行」这类动词加 2 分，工具调用成功加 1 分，计划里要求演示加 1 分。总分到 4 分且有代码或两个以上步骤才放行。这个判定是在 answer 节点结束之后才执行的，done 事件里才带结果，所以物理上不可能在回答结束前弹出。
> 第二个约束：**暂停要记录当前步骤，防止操作中断**。实现上，每一步先把握度 current_step 和这一条的 ScreenStep 记录落到数据库里，然后才去执行动作；暂停只是清掉一个 asyncio.Event，循环空转等待；恢复时从 current_step 继续。服务如果中途挂了，重启时会把 running 的会话标成 paused，提示可以从第 N 步继续。
> 具体循环是这样：截图，用 mss 抓主屏，截图上叠一层 0 到 1000 的坐标网格和刻度，转成 data URL；把目标、预设步骤、最近三步的动作和结果、以及截图一起给视觉模型，要求它只回一个 JSON：thought 加 action。
> 动作层支持得比较全：鼠标点击、双击、右键、拖动、滚轮；单键 enter、esc、f5；组合键 ctrl+shift+p、alt+tab、win+r 都行，写 "win+r" 或者 ["win","r"] 都能解析；还可以用 sequence 一次批量执行「打开运行框 → 输入 notepad → 回车」这种可预期的小流程。
> 提示词里我塞了一张快捷键工具箱：Win+R 打开程序、Win+E 资源管理器、Win+D 显示桌面、Alt+Tab 切窗口、Win+Tab 任务视图、Ctrl+Shift+Esc 任务管理器、Ctrl+Shift+P 命令面板，并且明确要求「能用快捷键就别猜坐标」—— 猜坐标是视觉模型最容易翻车的地方，用 Win+R 打开程序比在开始菜单里找图标稳得多。
> 另外两个防呆设计：一是操作后画面没反应不会马上放弃——先等 5 秒原地重试，再等 10 秒重试，还不行就判这个做法作废、逼模型换方案，全程不暂停打断你；二是模型给出非法键名或缺坐标时，会被规范化层拦下，这一轮降级成等待并把原因写进 thought，会话不会崩。
> 再往下一层还有个「经验库」：每一步执行完，把下一帧截图和上一帧一比——画面变了就记成有效做法，没变就记成无效做法并当场禁用，所以同一个坑它只会踩一次。经验按前台应用分库存进数据库，下次遇到记事本、VS Code 会优先复用有效做法。你在对话里说过的「用 Ctrl+Shift+P 打开命令面板」这种指示，也会被自动提取成经验。控制台底部有经验库面板，能看到它学到了什么，也能一键清空。
> 补一句权限边界：我给智能体接了本机文件工具，但**全部只读**——可以列目录、搜文件、读文本、用默认程序打开，但没有任何写入、删除、重命名的能力，exe 和脚本也直接拒绝。要改文件，只能走屏幕演示的键鼠操作，你能看见每一步、随时暂停。这样它就能精准地「打开你的某个文件」，又不会偷偷动你的硬盘。
> 知识库里我还加了一类「提示知识」：它不进向量库，而是每轮直接注入系统提示词，用来约束模型怎么做事——比如「屏幕操作优先用快捷键」「点击前先确认窗口标题」。按作用对象分给对话侧或屏幕侧。另外启动时会自动采集本机环境写成一条提示知识，里面有系统版本、Shell、Python 版本和一条硬约束：只给 Windows 命令，不要 apt、brew、sudo。实测问「怎么装依赖并设环境变量」，它给的是 pip install 和 $env:XXX，没有串到 Linux 去。
> 还有一个跨智能体的设计：对话智能体本来不知道你屏幕上开着什么，所以它有个工具叫 look_at_screen —— 当你问"我屏幕上这个报错是什么意思"，它会先截一张图交给视觉模型看，把看到的写进共享上下文；下一轮对话的提示词里就带上了"前台应用 + 画面内容"，屏幕演示开始时也会读同一份上下文。为了防止它乱截图，做了 8 秒限流和 5 分钟有效期，设置里也能一键关掉。
> 中文输入有个坑：pyautogui 只能打 ASCII。所以这里用 Win32 API 把文本写进剪贴板，再发 Ctrl+V，这样中文也能打进去。
> 更进一步，输入法其实是这类演示最容易翻车的地方：中文模式下用模拟按键敲 print("hi")，很容易变成全角括号、丢字符，甚至候选框把回车吃掉。所以文本输入现在默认全部走剪贴板粘贴，输入法完全不参与；落键之前还会把代码里的全角标点自动纠正成半角，比如把全角的括号换成半角，中文散文不会被误改。演示开始前我还会尝试把前台程序切到英文输入法，结束时自动还原——不过实测 Edge、VS Code 这类新式程序走的是 TSF 不是 IMM，切不了，所以真正兜底的是粘贴加全角纠正，界面也会如实提示「当前程序不支持自动切输入法」。
> 点得准这件事做了三层：一是 DPI 感知，抓屏和点击都声明 per-monitor v2，一个像素就是一个物理像素；二是每次点击后读真实光标位置，偏差超过 3px 就在结果里报出来；三是接了 UI Automation——资源管理器这种原生窗口可以直接读控件树，按钮叫什么、在哪个矩形，按序号点，完全不用估坐标。

> 安全上有三重兜底：鼠标甩到屏幕左上角触发 pyautogui 的 FAILSAFE；按全局快捷键 Ctrl+Alt+Shift+F12 立刻停掉所有演示（Win32 注册的全局热键，任何窗口下都生效，不用切回浏览器）；以及随时可点的暂停按钮。；还有演练模式、最大步数、动作白名单。

**代码位置**：
- `backend/app/agent/demo.py`：可用性判定
- `backend/app/screen_agent/controller.py`：会话状态机、循环、暂停续跑
- `backend/app/screen_agent/capture.py` / `actions.py`
- `frontend/src/components/ScreenModal.vue`：控制台

## 附：演示口径（万一被问到）

- **为什么不用 WebSocket**：只需要服务端单向推送，SSE 更轻，且能自动重连。
- **为什么 mock 模型不算作弊**：它实现的是 LangChain 的 `BaseChatModel` 协议，走的是同一张图、同一套工具、同一套流式，只是把「模型输出」换成了规则生成，用于离线演示与自动化测试。
- **工具沙箱安全吗**：不安全，是「受限执行」不是「安全隔离」，靠子进程 + 超时 + 危险调用拦截，真实产品要上容器。
- **屏幕演示会不会乱点**：有三重保护——演练模式、FAILSAFE 左上角中止、最大步数；而且必须用户手动点启动。
- **Qdrant embedded 算不算用了 Qdrant**：算，同一套引擎，只是存储放本地文件；改一个环境变量就切服务端。
